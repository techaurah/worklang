# Security Policy

## Reporting a vulnerability

Please do not open a public issue for a security problem.

- Preferred: use GitHub's private vulnerability reporting on this
  repository (Security tab, "Report a vulnerability").
- Or email the maintainers via the contact route at
  https://techaurah.com and put "WorkLang security" in the subject.

You can expect an acknowledgement within a few days. Please give us a
reasonable window to fix and release before disclosing publicly.

## Supported versions

| Version | Supported |
|---|---|
| 0.1.x | Yes |
| Earlier | No (0.1.0 is the first release) |

## Data handling rules

- Corpus v0 is 100 percent synthetic, generated by TechAura's own
  simulators, and contains no real customer data. If you find real
  personal data anywhere in this repository, treat that as a
  security report and use the private route above.
- The schema has no field that can hold a name, an email address, a
  phone number, or message text: those are dropped at tokenisation
  by design. A change that adds a way to carry them is a privacy
  change, not a feature, and needs a security discussion first.
- Nothing in this repository needs credentials to run. Never commit
  credentials or a real `.env`.

## Model weights

- The demo samples from the trained weights at
  `demo/worklang-mini-v0.pt`. A PyTorch checkpoint from an
  untrusted source can execute code when it is loaded, so only
  load checkpoints that ship in this repository or in a release of
  it, and treat any other checkpoint file as untrusted input.
